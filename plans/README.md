## Goal

Migrate the MS Access MCP server from Python to ReScript v12 for type
safety, database-interaction layer first, deployed primarily as a local
tool for AI harnesses. The migration is 1:1 on behavior: same inputs,
outputs, and errors as the Python original (verified differentially by
plan 007). Full plan set and methodology classification below.

## Methodology classification rule

Each phase is labeled with how it is built:

- **STRICT TDD** — the behavior is already fully specified (Python oracle
  + existing openspec specs) and the work is local/pure. No new design
  decisions. Red-green-refactor against rescript-test; tests are written
  first, always.
- **SDD** — the phase makes NEW design decisions (FFI binding surfaces,
  async models, public API contracts) that must be proposed, specified,
  and designed before implementation, via the repo's openspec workflow.
  Note: the repo's SDD rule (`openspec/config.yaml`) is
  `apply: Implement tasks following strict TDD` — so SDD phases are not
  TDD-free; they add spec/design stages IN FRONT of TDD implementation.
- **NEITHER** — configuration, verification infrastructure, or decision

## Plan authoring standards (hardened 2026-08-25 after plan 015/021/022 execution failures)

These rules exist because executing the original plan set surfaced five
systemic failure modes. Every NEW or AMENDED plan must follow them:

1. **Verify claims at authoring time, not just execution time.** Every
   "Current state" excerpt (line numbers, type signatures, method counts)
   must be read from the live files BEFORE the plan is written. Plan 015's
   design claimed 18 schema methods (real: 22), a self-taking
   `OdbcSchemaReader` (real: query seam), and `insertData: JSON.t` (real:
   `dict<JSON.t>`) — each error cost a full SDD cycle re-run.
2. **Fresh-build verification only.** Any "suite is green" claim must come
   from `rescript clean` + full rebuild. Cached `lib/bs/*.mjs` artifacts
   produced the false 553/553/0 baseline that hid the aggregator breakage
   for three cycles.
3. **Environment quirks go in the plan header.** Plans executing on this
   machine must state: (a) pnpm via `cmd.exe /c` wrapper + log files
   (PowerShell wrapper hides output); (b) `pnpm install --ignore-scripts`
   when winax/node-gyp/Python fail; (c) `.venv\Scripts\python.exe`, never
   `uv`.
4. **Design verbatim is binding for executors.** Apply-phase agents must
   copy design snippets exactly; deviation is a STOP, not improvisation.
   Plan 015's first apply attempt rewrote `insertData`'s signature and
   dropped labeled args off-script, corrupting the working tree.
5. **Clean tree is a precondition.** Every plan's drift check starts with
   `git status` expecting zero uncommitted `src/`/`test/` changes. A dirty
   tree at plan start is itself a STOP. Plan 024 enforces this globally.
6. **`rescript clean` does NOT clear `rescript-mcp/test/*.mjs`** — only
   `lib/bs/`. Stale compiled test artifacts (e.g. orphans left after a
   `.res` source rewrite) silently crash the test runner. Any plan that
   rewrites test source shape must either delete the stale `.mjs` files
   or document the gap. Plan 025 enforces this for the current orphans.
7. **Fresh-build from empty `lib/bs` is the ONLY trustworthy gate.**
   Incremental builds with cached `.bs.js` artifacts mask latent type
   errors that would otherwise fail a true clean compile. Plan 025
   shipped a "green" suite that was actually passing on cached state;
   plan 024's fresh build exposed `Instances.res:34` declaring
   `insertData: (string, JSON.t)` instead of `dict<JSON.t>` (the live
   `OdbcAdapter.insertData` signature). Every plan's "suite is green"
   claim MUST come from `rescript clean` + full rebuild + test, full
   stop. Cached `lib/bs` is not evidence.
8. **Grep gates need precision.** "No `Fakes` in Facade.res" can be
   read two ways — strict (zero substring matches) or intent (no
   public-type coupling to the Fakes module). Plan 015's executor
   introduced `_rawDataAdapter: option<Fakes.FakeOdbcAdapter.t>` and
   `_rawSchemaAdapter: option<Fakes.FakeSchemaAdapter.t>` as
   `_`-prefixed internal test-injection helpers (preserves test
   ergonomics without exposing the binding's public type). Strict
   grep reads 2 matches; intent reads 0 (public coupling is gone).
   Plan 015's plan gate text was over-strict; amended to
   "no PUBLIC Fakes coupling" in the dependency note. Future plan
   grep gates should specify the intent, not just the substring.

## Findings considered and rejected

- Root pnpm workspace (merging `rescript-mcp/` + `frontend/` under root
  `pnpm-workspace.yaml`): rejected — `frontend/` already works as an
  independent workspace; a self-contained `rescript-mcp/` package mirrors
  that precedent with zero blast radius.
- `rescript-node` as the Node bindings package: does not exist. The
  verified package is `rescript-nodejs@17.0.0` (peer: rescript ^12.2.0).
- Hand-rolled MCP protocol implementation instead of the official SDK:
  rejected — `@modelcontextprotocol/sdk` is the standard; binding FFI is
  isolated in `Bindings/McpSdk.res` regardless.
- Migrating HTTP transport, API-key auth, telemetry, sessions, rate
  limiting, LLM tools, and the 23-tool full surface in this wave:
  deferred — the user's deployment model is local/AI-harness-first; stdio
  needs none of it (matching Python's stdio mode, which requires no
  `ACCESS_MCP_API_KEY`). Reopening any of it is a new SDD change.
- TDD for the parity harness itself: rejected by classification — it is
  verification infrastructure; its self-test is the mutation check
  (plan 007, Step 5).
- ODBC-side `%raw` migration (OdbcAdapter ~17 blocks, SqlBuilder ~11,
  OdbcSchemaReader 2) into the 010+ `Js/*.mts` bridge: deferred, not
  rejected — kept out of plans 010–013 to bound the COM-focused slice;
  re-audit after 012 lands.
- Fixing the 2 pre-existing OdbcAdapterTest failures inside plan 007
  execution: rejected — suite hygiene belongs in its own bounded plan (017)
  so parity sessions never re-litigate whether red means "mismatch" or
  "known baseline".
- Folding the facade composition-root fix into plan 007 as a "Step 0":
  rejected — the adapter instance types are a seam contract consumed by
  BOTH 007 (parity driver) and 008 (MCP composition root); it gets its own
  compact SDD cycle (015) with archived artifacts.
- COM stack proof inside plan 016: rejected — all 17 v1 facade operations
  are ODBC-safe; COM parity is moot until a future facade phase adds COM
  operations (see plan 018 amendment 6).

## Key verified facts (shared across plans)

- ReScript 12 stable (Nov 2025); Node >= 22 for the compiler, but
  `rescript-test@8.0.1` requires Node >= 24 → Node 24 LTS pinned.
- pnpm gotcha: `@rescript/runtime` must be a DIRECT dependency under pnpm
  strict isolation (official docs).
- `odbc` npm package (IBM/node-odbc 2.5.x): promise API, prebuilt NAPI
  win32-x64 binaries, needs the ACE ODBC driver at runtime.
- `winax` (node-activex 3.6.x): in-process COM IDispatch (the chosen COM
  strategy), node-gyp build, NO prebuilds → VS Build Tools prerequisite
  (plan 004 Stage 0 gates on it).
- `rescript.json` v12 schema: `dependencies` / `dev-dependencies` fields
  (rescript-nodejs → dependencies; rescript-test → dev-dependencies).
- rescript-test API: `test`, `testAsync`, `assertion` with custom
  comparators, `createTestWith` for setup/teardown; run via `retest` glob.
